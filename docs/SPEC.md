# مواصفات تطبيق وِجهة الشمال — قابلة للتنفيذ

> نسخة Prototype حالية: Next.js (Web/PWA).  
> مسار الإنتاج المقترح أدناه. هذا المستند مرجع تنفيذ للإدارة والفريق.

---

## 1) الرؤية والمنصة المستهدفة

| البند | القرار |
|------|--------|
| المنتج | تطبيق بلاغات واقتراحات للمستفيد + لوحة موظف |
| اللغة | العربية RTL بالكامل |
| المنصة الأولى | **Web Progressive Web App (PWA)** عبر Next.js — أسرع للإنباثون والنشر |
| المنصة التالية | غلاف موبايل (Capacitor) لنشر iOS/Android من نفس الكود |
| البديل الموبايل الأصلي | React Native / Expo إن رُغب لاحقًا بتطبيق متجر مستقل |

**لماذا PWA الآن؟** نفس منطق النموذج الحالي، نشر فوري (Vercel/GitHub Pages)، دعم إشعارات ويب، بدون انتظار مراجعة المتاجر.

## 2) خريطة الشاشات والتنقل

```
Splash (ابدأ)
  └─ الرئيسية
       └─ بطاقة مشروع «وِجهة الشمال»  ← ضغط
            └─ صفحة المشروع (ثانوية)
                 ├─ إبلاغ → نموذج → تأكيد + رقم تذكرة → تتبع
                 ├─ اقتراح → نموذج → تأكيد + رقم تذكرة → تتبع/تعليق
                 ├─ متابعة الطلب
                 └─ دخول الموظف → لوحة (بلاغات/اقتراحات/إعادة توجيه)
```

### شريط تنقل سفلي (موبايل/ويب ضيق)
- الرئيسية
- مشروعي (صفحة المشروع)
- متابعة
- الموظف

### قائمة هامبرغر (ديسكتوب/تابلت)
نفس الوجهات + تسجيل خروج الموظف عند تسجيل الدخول.

## 3) واجهات المستخدم — تفاصيل الحقول

### 3.1 الرئيسية
- شعار صغير + اسم التطبيق
- بطاقة مشروع واحدة كبيرة: أيقونة، عنوان، وصف قصير، CTA «الدخول للمشروع»
- بدون ازدحام إحصائيات في الـ Hero

### 3.2 صفحة المشروع
ثلاث بطاقات كبيرة قابلة للضغط:
1. **إبلاغ** — أيقونة تحذير
2. **اقتراح** — أيقونة لمبة/فكرة
3. **دخول الموظف** — أيقونة درع/مستخدم

### 3.3 نموذج إبلاغ
| الحقل | النوع | إلزامي | ملاحظات |
|------|------|--------|---------|
| العنوان | نص قصير | نعم | ≤ 120 حرف |
| الوصف | نص طويل | نعم | ≤ 1000 حرف |
| الأولوية | منخفضة/متوسطة/عالية | نعم | افتراضي: متوسطة |
| الموقع | خريطة + عنوان | لا | Geolocation + خرائط |
| مرفقات | صور (كاميرا/ملفات) | لا | ≤ 5 ملفات، 8MB للملف |
| الإرسال | زر أساسي | — | بعد النجاح: رقم تذكرة |

### 3.4 نموذج اقتراح
| الحقل | النوع | إلزامي | ملاحظات |
|------|------|--------|---------|
| العنوان | نص قصير | نعم | |
| التفاصيل | نص طويل | نعم | |
| الفئة | قائمة | نعم | خدمات/بنية/تجربة مستفيد/أخرى |
| أرغب بالمتابعة | نعم/لا | نعم | إن نعم يُفعّل مسار التعليقات |
| مرفقات | اختياري | لا | |
| الإرسال | زر أساسي | — | رقم تذكرة + إمكانية تعليق لاحقًا |

### 3.5 دخول الموظف
- اسم مستخدم + كلمة مرور (النموذج الحالي)
- مسار إنتاج: OAuth 2.0 / OpenID (Microsoft Entra أو نفاذ وطني لاحقًا)
- أدوار: `staff` | `manager`

### 3.6 لوحة الموظف
- فلترة: النوع (بلاغ/اقتراح)، الحالة، الأولوية، الجهة
- بطاقة طلب: رقم، ملخص، مقترح جهة، قائمة جهات، تأكيد إعادة توجيه
- للمدير: مؤشرات (عدد جديد، متوسط زمن التوجيه)

## 4) الحالات وسجل زمني

حالات موحدة للتذكرة:

`received` → `classified` → `awaiting_staff` → `routed` → `in_progress` → `resolved` | `closed`

كل انتقال يُسجَّل في Timeline:
- الوقت، الممثل (مستفيد/نظام/موظف)، ملاحظة قصيرة

## 5) مواصفات API (REST)

Base: `/api/v1`  
Auth: Bearer JWT (مستفيد اختياري للـ MVP؛ موظف إلزامي)

### Auth
| Method | Path | وصف |
|--------|------|-----|
| POST | `/auth/login` | مستخدم/كلمة مرور → JWT + role |
| POST | `/auth/oauth/callback` | إكمال OAuth |
| POST | `/auth/logout` | إبطال الجلسة |

### Tickets
| Method | Path | وصف |
|--------|------|-----|
| POST | `/tickets` | إنشاء بلاغ أو اقتراح `{type,title,body,...}` |
| GET | `/tickets/:id` | تفاصيل + timeline |
| GET | `/tickets?type=&status=` | قائمة (موظف) |
| PATCH | `/tickets/:id/status` | تحديث حالة |
| POST | `/tickets/:id/route` | إعادة توجيه لجهة |
| POST | `/tickets/:id/comments` | تعليق (اقتراح/متابعة) |
| POST | `/tickets/:id/attachments` | رفع مرفق (multipart) |

### مثال إنشاء بلاغ
```json
POST /api/v1/tickets
{
  "type": "report",
  "title": "تسرب مياه بجانب مدرسة",
  "body": "...",
  "priority": "medium",
  "location": { "lat": 30.97, "lng": 41.03, "label": "عرعر" }
}
```
Response:
```json
{
  "id": "NB-2026-0145",
  "status": "awaiting_staff",
  "suggestedSector": "وزارة المياه"
}
```

## 6) مخطط قاعدة البيانات (مختصر)

```
users(id, username, password_hash, role, created_at)
tickets(id, type[report|suggestion], title, body, priority,
        category, follow_up, status, suggested_sector,
        assigned_sector, location_json, created_by, created_at)
attachments(id, ticket_id, storage_key, mime, size, created_at)
ticket_events(id, ticket_id, actor_type, actor_id, event, note, created_at)
comments(id, ticket_id, author_id, body, created_at)
audit_logs(id, actor_id, action, meta_json, created_at)
```

تخزين الملفات: Object Storage (S3-compatible) مع روابط موقّتة؛ لا تحفظ الملفات داخل DB.

## 7) الأمن

- HTTPS فقط، HSTS
- كلمات مرور: Argon2/bcrypt
- JWT قصير العمر + Refresh آمن (httpOnly cookie للويب)
- صلاحيات على مستوى الدور (RBAC)
- التحقق من نوع/حجم المرفقات + فحص malware لاحقًا
- تشفير الحقول الحساسة في الراحة إن وُجدت بيانات شخصية
- سجلات تدقيق لكل إعادة توجيه وتغيير حالة
- Rate limiting على login وإنشاء التذاكر

## 12) معايير قبول الـ MVP

1. من Splash → رئيسية → مشروع → إبلاغ/اقتراح خلال ≤ 3 نقرات.
2. كل إرسال ناجح يُظهر رقم تذكرة واضح.
3. الموظف يدخل ويؤكد إعادة توجيه حسب نوع الطلب.
4. الواجهة عربية RTL ومتجاوبة للجوال.
5. لا اتصال بأنظمة حكومية حقيقية في مرحلة الـ Prototype (إفصاح ظاهر).
